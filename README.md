# QA Test: Restful-Booker API

Тестовое задание на позицию QA-инженера. Проект содержит тест-кейсы и баг-репорты для REST API сервиса [Restful-Booker](https://restful-booker.herokuapp.com/apidoc/index.html).

---

## 📋 Описание проекта

**Цель:** Провести тестирование REST API сервиса Restful-Booker, составить тест-кейсы, создать Postman-коллекцию с автоматическими проверками и зафиксировать найденные баги.

**Что было сделано:**
- ✅ Изучена документация API.
- ✅ Составлены 28 тест-кейсов (10 позитивных, 18 негативных) для всех эндпоинтов.
- ✅ Создана Postman-коллекция с автоматическими проверками (Tests).
- ✅ Настроен Pre-request Script для автосоздания брони (тесты работают и по отдельности, и в RUN).
- ✅ Проведён полный прогон коллекции через Postman Runner.
- ✅ Зафиксированы и оформлены 12 баг-репортов.
- ✅ Настроен автосоздание брони для независимого запуска тестов.

## 🐞 Найденные баги

В ходе тестирования обнаружено **12 багов**:

| Приоритет    | Количество |
| :---         | :---       |
| **Critical** | 3          |
| **High**     | 8          |
| **Medium**   | 1          |

**Топ-3 критических бага:**
1. **AUTH-4:** Сервер выдает токен при невалидной паре логин/пароль.
2. **AUTH-5:** Сервер выдает токен при пустом теле запроса.
3. **BOOKING-7:** Сервер создает бронь с `checkin > checkout`

**Особенности сервера (не баги):**
- Повторное удаление брони возвращает `405 Method Not Allowed` вместо `404 Not Found` — это ожидаемое поведение Restful-Booker..

## 🚀 Как запустить тесты

### Требования
- Postman 

### Через Postman
1. **Импортируй коллекцию** `postman/restful-booker.postman_collection.json`.
2. **Создай Environment** с переменными:
   - `authToken` (пустое)
   - `bookingId` (пустое)
   - `bookingData` (пустое)
   - `firstName` (пустое)
   - `deletedBookingId` (пустое)
3. **Выбери окружение** в правом верхнем углу.
4. **Запусти коллекцию** через **Runner**

**🛠 Стек технологий**
Postman — создание и запуск API-тестов
JavaScript — написание проверок в Postman Tests
Excel — оформление тест-кейсов и баг-репортов

🔧 Особенности коллекции
Pre-request Script на уровне коллекции
Коллекция содержит Pre-request Script, который автоматически создаёт бронь, если её нет. Это позволяет запускать тесты по отдельности без необходимости сначала запускать POST /booking.

Логика работы:

✅ Пропускает POST /auth, GET /ping, POST /booking, GET /booking (список).

✅ Создаёт бронь для GET/PUT/PATCH/DELETE /booking/{{bookingId}}, если bookingId нет.

✅ Создаёт и сразу удаляет бронь для теста удаление уже удалённого, если deletedBookingId нет

📌 Что проверяется в тестах
AUTH
Создание токена с валидными данными.

Пустой username / password.

Невалидная пара логин/пароль.

Пустое тело запроса.

BOOKING (POST)
Создание брони с валидными данными.

Пустые обязательные поля (firstname, lastname, totalprice, bookingdates).

Отрицательный totalprice.

checkin > checkout.

Неверный формат даты.

CRUD (GET, PUT, PATCH, DELETE)
Получение списка броней и фильтрация по firstname.

Получение брони по ID и несуществующей брони.

Обновление с авторизацией и без.

Частичное обновление (PATCH).

Удаление с авторизацией, без авторизации, повторное удаление.

PING
Проверка доступности сервиса.
